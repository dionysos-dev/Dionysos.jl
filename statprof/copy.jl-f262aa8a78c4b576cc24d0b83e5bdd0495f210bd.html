290 """
291 sorted_variable_sets_by_cost(dest::MOI.ModelLike, src::MOI.ModelLike)
292
293 Return a `Vector{Type}` of the set types corresponding to `VariableIndex` and
294 `VectorOfVariables` constraints in the order in which they should be added.
295
296 ## How the order is computed
297
298 The sorting happens in the `_cost_of_bridging` function and has three main
299 considerations:
300
301 1. First add sets for which the `VariableBridgingCost` is `0`. This ensures that
302 we minimize the number of variable bridges that get added.
303 2. Then add sets for which the VariableBridgingCost is smaller than the
304 `ConstraintBridgingCost` so they can get added with
305 `add_constrained_variable(s)`.
306 3. Finally, break any remaining ties in favor of `AbstractVectorSet`s. This
307 ensures we attempt to add large blocks of variables (for example, such as PSD
308 matrices) before we add things like variable bounds.
309
310 ## Why the order is important
311
312 The order is important because some solvers require variables to be added in
313 particular order, and the order can also impact the bridging decisions.
314
315 We favor adding first variables that won't use variables bridges because then
316 the variable constraints on the same variable can still be added as
317 `VariableIndex` or `VectorOfVariables` constraints.
318
319 If a variable does need variable bridges and is part of another variable
320 constraint, then the other variable constraint will be force-bridged into affine
321 constraints, so there is a hidden cost in terms of number of additional number
322 of bridges that will need to be used.
323
324 In fact, if the order does matter (in the sense that changing the order of the
325 vector returned by this function leads to a different formulation), it means the
326 variable is in at least one other variable constraint. Thus, in a sense we
327 could do `x - y + sign(x)`` but `!iszero(x), x - y` is fine.
328
329 ## Example
330
331 A key example is Pajarito. It supports `VariableIndex`-in-`Integer` and
332 `VectorAffine`-in-`Nonnegatives`. If the user writes:
333 ```julia
334 @variable(model, x >= 1, Int)
335 ```
336 then we need to add two variable-related constraints:
337 * `VariableIndex`-in-`Integer`
338 * `VariableIndex`-in-`GreaterThan`
339 The first is natively supported and the variable and constraint bridging cost is
340 0. The second must be bridged to `VectorAffineFunction`-in-`Nonnegatives` via
341 `x - 1 in Nonnegatives(1)`, and the variable and constraint bridging cost is
342 `1` in both cases.
343
344 If the order is `[Integer, GreaterThan]`, then we add `x ∈ Integer` and
345 `x - 1 in Nonnegatives`. Both are natively supported and it only requires a
346 single constraint bridge.
347
348 If the order is `[GreaterThan, Integer]`, then we add a new variable constrained
349 to `y ∈ Nonnegatives` and end up with an expression from the variable bridge of
350 `x = y + 1`. Then when we add the Integer constraint, we get `y + 1 in Integer`,
351 which is not natively supported. Therefore, we need to add `y + 1 - z ∈ Zeros`
352 and `z ∈ Integer`. Oops. This cost an extra variable, a variable bridge of
353 `x = y + 1`and a `Zeros` constraint.
354
355 Unfortunately, we don't have a good way of computing the updated costs for other
356 constraints if a variable bridge is chosen.
357 """

440 # This function is a heuristic that checks whether `f` should be added via
441 # `MOI.add_constrained_variables`.
442 function _is_variable_cone(
443 cache::_CopyVariablesWithSetCache,
444 f::MOI.VectorOfVariables,
445 )
446 if isempty(f.variables)
447 # If the dimension is `0`, `f` cannot be added via
448 # `add_constrained_variables`
449 return false
450 end
451 offset = cache.variable_to_column[f.variables[1]] - 1
452 for (i, xi) in enumerate(f.variables)
453 if xi in cache.variables_with_domain
454 # The function contains at least one element that is already
455 # assigned to a domain. We can't add `f` via
456 # `add_constrained_variables`
457 return false
458 elseif cache.variable_to_column[xi] != offset + i
459 # The variables in the function are not contiguous in their column
460 # ordering. In theory, we could add `f` via `add_constrained_variables`,
461 # but this would introduce a permutation so we choose not to.
462 return false
463 end
464 end
465 return true
466 end

561 """
562 ModelFilter(filter::Function, model::MOI.ModelLike)
563
564 A layer to filter out various components of `model`.
565
566 The filter function takes a single argument, which is each element from the list
567 returned by the attributes below. It returns `true` if the element should be
568 visible in the filtered model and `false` otherwise.
569
570 The components that are filtered are:
571
572 * Entire constraint types via:
573 * `MOI.ListOfConstraintTypesPresent`
574 * Individual constraints via:
575 * `MOI.ListOfConstraintIndices{F,S}`
576 * Specific attributes via:
577 * `MOI.ListOfModelAttributesSet`
578 * `MOI.ListOfConstraintAttributesSet`
579 * `MOI.ListOfVariableAttributesSet`
580
581 !!! warning
582 The list of attributes filtered may change in a future release. You should
583 write functions that are generic and not limited to the five types listed
584 above. Thus, you should probably define a fallback `filter(::Any) = true`.
585
586 See below for examples of how this works.
587
588 !!! note
589 This layer has a limited scope. It is intended by be used in conjunction
590 with `MOI.copy_to`.
591
592 ## Example: copy model excluding integer constraints
593
594 Use the `do` syntax to provide a single function.
595
596 ```julia
597 filtered_src = MOI.Utilities.ModelFilter(src) do item
598 return item != (MOI.VariableIndex, MOI.Integer)
599 end
600 MOI.copy_to(dest, filtered_src)
601 ```
602
603 ## Example: copy model excluding names
604
605 Use type dispatch to simplify the implementation:
606
607 ```julia
608 my_filter(::Any) = true # Note the generic fallback
609 my_filter(::MOI.VariableName) = false
610 my_filter(::MOI.ConstraintName) = false
611 filtered_src = MOI.Utilities.ModelFilter(my_filter, src)
612 MOI.copy_to(dest, filtered_src)
613 ```
614
615 ## Example: copy irreducible infeasible subsystem
616
617 ```julia
618 my_filter(::Any) = true # Note the generic fallback
619 function my_filter(ci::MOI.ConstraintIndex)
620 status = MOI.get(dest, MOI.ConstraintConflictStatus(), ci)
621 return status != MOI.NOT_IN_CONFLICT
622 end
623 filtered_src = MOI.Utilities.ModelFilter(my_filter, src)
624 MOI.copy_to(dest, filtered_src)
625 ```
626 """

750 function _copy_free_variables(dest::MOI.ModelLike, index_map::IndexMap, vis_src)
751 if length(vis_src) == length(index_map.var_map)
752 return # All variables already added
753 end
754 x = MOI.add_variables(dest, length(vis_src) - length(index_map.var_map))
755 i = 1
756 for vi in vis_src
757 if !haskey(index_map, vi)
758 index_map[vi] = x[i]
759 i += 1
760 end
761 end
762 @assert i == length(x) + 1
