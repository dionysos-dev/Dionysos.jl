9 @constraint(model, name, expr, args...; kwargs...)
10 @constraint(model, name[index_sets...], expr, args...; kwargs...)
11
12 Add a constraint described by the expression `expr`.
13
14 The `name` argument is optional. If index sets are passed, a container is built
15 and the constraint may depend on the indices of the index sets.
16
17 The expression `expr` may be one of following forms:
18
19 * `func in set`, constraining the function `func` to belong to the set `set`,
20 which is either a [`MOI.AbstractSet`](@ref) or one of the JuMP shortcuts like
21 [`SecondOrderCone`](@ref) or [`PSDCone`](@ref)
22
23 * `a <op> b`, where `<op>` is one of `==`, `≥`, `>=`, `≤`, `<=`
24
25 * `l <= f <= u` or `u >= f >= l`, constraining the expression `f` to lie
26 between `l` and `u`
27
28 * `f(x) ⟂ x`, which defines a complementarity constraint
29
30 * `z --> {expr}`, which defines an indicator constraint that activates
31 when `z` is `1`
32
33 * `!z --> {expr}`, which defines an indicator constraint that activates
34 when `z` is `0`
35
36 * `z <--> {expr}`, which defines a reified constraint
37
38 * `expr := rhs`, which defines a Boolean equality constraint
39
40 Broadcasted comparison operators like `.==` are also supported for the case when
41 the left- and right-hand sides of the comparison operator are arrays.
42
43 JuMP extensions may additionally provide support for constraint expressions
44 which are not listed here.
45
46 ## Keyword arguments
47
48 * `base_name`: sets the name prefix used to generate constraint names. It
49 corresponds to the constraint name for scalar constraints, otherwise, the
50 constraint names are set to `base_name[...]` for each index `...`.
51
52 * `container = :Auto`: force the container type by passing `container = Array`,
53 `container = DenseAxisArray`, `container = SparseAxisArray`, or any another
54 container type which is supported by a JuMP extension.
55
56 * `set_string_name::Bool = true`: control whether to set the [`MOI.ConstraintName`](@ref)
57 attribute. Passing `set_string_name = false` can improve performance.
58
59 Other keyword arguments may be supported by JuMP extensions.
60
61 ## Example
62
63 ```jldoctest
64 julia> model = Model();
65
66 julia> @variable(model, x[1:3]);
67
68 julia> @variable(model, z, Bin);
69
70 julia> @constraint(model, x in SecondOrderCone())
71 [x[1], x[2], x[3]] ∈ MathOptInterface.SecondOrderCone(3)
72
73 julia> @constraint(model, [i in 1:3], x[i] == i)
74 3-element Vector{ConstraintRef{Model, MathOptInterface.ConstraintIndex{MathOptInterface.ScalarAffineFunction{Float64}, MathOptInterface.EqualTo{Float64}}, ScalarShape}}:
75 x[1] = 1
76 x[2] = 2
77 x[3] = 3
78
79 julia> @constraint(model, x .== [1, 2, 3])
80 3-element Vector{ConstraintRef{Model, MathOptInterface.ConstraintIndex{MathOptInterface.ScalarAffineFunction{Float64}, MathOptInterface.EqualTo{Float64}}, ScalarShape}}:
81 x[1] = 1
82 x[2] = 2
83 x[3] = 3
84
85 julia> @constraint(model, con_name, 1 <= x[1] + x[2] <= 3)
86 con_name : x[1] + x[2] ∈ [1, 3]
87
88 julia> @constraint(model, con_perp[i in 1:3], x[i] - 1 ⟂ x[i])
89 3-element Vector{ConstraintRef{Model, MathOptInterface.ConstraintIndex{MathOptInterface.VectorAffineFunction{Float64}, MathOptInterface.Complements}, VectorShape}}:
90 con_perp[1] : [x[1] - 1, x[1]] ∈ MathOptInterface.Complements(2)

273 """
274 parse_constraint(error_fn::Function, expr::Expr)
275
276 The entry-point for all constraint-related parsing.
277
278 ## Arguments
279
280 * The `error_fn` function is passed everywhere to provide better error messages
281 * `expr` comes from the `@constraint` macro. There are two possibilities:
282 * `@constraint(model, expr)`
283 * `@constraint(model, name[args], expr)`
284 In both cases, `expr` is the main component of the constraint.
285
286 ## Supported syntax
287
288 JuMP currently supports the following `expr` objects:
289 * `lhs <= rhs`
290 * `lhs == rhs`
291 * `lhs >= rhs`
292 * `l <= body <= u`
293 * `u >= body >= l`
294 * `lhs ⟂ rhs`
295 * `lhs in rhs`
296 * `lhs ∈ rhs`
297 * `z --> {constraint}`
298 * `!z --> {constraint}`
299 * `z <--> {constraint}`
300 * `!z <--> {constraint}`
301 * `z => {constraint}`
302 * `!z => {constraint}`
303 as well as all broadcasted variants.
304
305 ## Extensions
306
307 The infrastructure behind `parse_constraint` is extendable. See
308 [`parse_constraint_head`](@ref) and [`parse_constraint_call`](@ref) for details.
309 """
310 function parse_constraint(error_fn::Function, expr::Expr)

312 end

329 """
330 _desparsify(x)
331
332 If `x` is an `AbstractSparseArray`, return the dense equivalent, otherwise just
333 return `x`.
334
335 This function is used in `_build_constraint`.
336
337 ## Why is this needed?
338
339 When broadcasting `f.(x)` over an `AbstractSparseArray` `x`, Julia first calls
340 the equivalent of `f(zero(eltype(x))`. Here's an example:
341
342 ```jldoctest
343 julia> import SparseArrays
344
345 julia> foo(x) = (println("Calling \$(x)"); x)
346 foo (generic function with 1 method)
347
348 julia> foo.(SparseArrays.sparsevec([1, 2], [1, 2]))
349 Calling 1
350 Calling 2
351 2-element SparseArrays.SparseVector{Int64, Int64} with 2 stored entries:
352 [1] = 1
353 [2] = 2
354 ```
355
356 However, if `f` is mutating, this can have serious consequences! In our case,
357 broadcasting `build_constraint` will add a new `0 = 0` constraint.
358
359 Sparse arrays most-often arise when some input data to the constraint is sparse
360 (for example, a constant vector or matrix). Due to promotion and arithmetic, this
361 results in a constraint function that is represented by an `AbstractSparseArray`,
362 but is actually dense. Thus, we can safely `collect` the matrix into a dense
363 array.
364
365 If the function is sparse, it's not obvious what to do. What is the "zero"
366 element of the result? What does it mean to broadcast `build_constraint` over a
367 sparse array adding scalar constraints? This likely means that the user is using
368 the wrong data structure. For simplicity, let's also call `collect` into a dense
369 array, and wait for complaints.
370 """
371 _desparsify(x::SparseArrays.AbstractSparseArray) = collect(x)
372
373 _desparsify(x) = x

376 parse_constraint_head(error_fn::Function, ::Val{head}, args...)
377
378 Implement this method to intercept the parsing of an expression with head
379 `head`.
380
381 !!! warning
382 Extending the constraint macro at parse time is an advanced operation and
383 has the potential to interfere with existing JuMP syntax. Please discuss
384 with the [developer chatroom](https://jump.dev/chatroom) before
385 publishing any code that implements these methods.
386
387 ## Arguments
388
389 * `error_fn`: a function that accepts a `String` and throws the string as an
390 error, along with some descriptive information of the macro from which it was
391 thrown.
392 * `head`: the `.head` field of the `Expr` to intercept
393 * `args...`: the `.args` field of the `Expr`.
394
395 ## Returns
396
397 This function must return:
398
399 * `is_vectorized::Bool`: whether the expression represents a broadcasted
400 expression like `x .<= 1`
401 * `parse_code::Expr`: an expression containing any setup or rewriting code that
402 needs to be called before `build_constraint`
403 * `build_code::Expr`: an expression that calls `build_constraint(` or
404 `build_constraint.(` depending on `is_vectorized`.
405
406 ## Existing implementations
407
408 JuMP currently implements:
409
410 * `::Val{:call}`, which forwards calls to [`parse_constraint_call`](@ref)
411 * `::Val{:comparison}`, which handles the special case of `l <= body <= u`.
412
413 See also: [`parse_constraint_call`](@ref), [`build_constraint`](@ref)
414 """
415 function parse_constraint_head(error_fn::Function, ::Val{T}, args...) where {T}
416 return error_fn(
417 "Unsupported constraint expression: we don't know how to parse " *
418 "constraints containing expressions of type :$T.\n\nIf you are " *
419 "writing a JuMP extension, implement " *
420 "`parse_constraint_head(::Function, ::Val{:$T}, args...)",
421 )
422 end

455 function parse_constraint_head(
456 error_fn::Function,
457 ::Val{:comparison},
458 lb,
459 lsign::Symbol,
460 aff,
461 rsign::Symbol,
462 ub,
463 )
464 lsign, lvectorized = _check_vectorized(lsign)
465 rsign, rvectorized = _check_vectorized(rsign)
466 if lvectorized != rvectorized
467 error_fn("Operators are inconsistently vectorized.")
468 end
469 if lsign in (:(<=), :≤) && rsign in (:(<=), :≤)
470 # Nothing. What we expect.
471 elseif lsign in (:(>=), :≥) && rsign in (:(>=), :≥)
472 # Flip lb and ub
473 lb, ub = ub, lb
474 else
475 error_fn(
476 "unsupported mix of comparison operators " *
477 "`$lb $lsign ... $rsign $ub`.\n\n" *
478 "Two-sided rows must of the form `$lb <= ... <= $ub` or " *
479 "`$ub >= ... >= $lb`.",
480 )
481 end
482 new_aff, parse_aff = _rewrite_expression(aff)
483 new_lb, parse_lb = _rewrite_expression(lb)
484 new_ub, parse_ub = _rewrite_expression(ub)
485 parse_code = quote
486 $parse_aff
487 $parse_lb
488 $parse_ub
489 end
490 build_call = if lvectorized
491 :(build_constraint.(
492 $error_fn,
493 _desparsify($new_aff),
494 _desparsify($new_lb),
495 _desparsify($new_ub),
496 ))
497 else
498 :(build_constraint($error_fn, $new_aff, $new_lb, $new_ub))
499 end
500 return lvectorized, parse_code, build_call
501 end

504 operator_to_set(error_fn::Function, ::Val{sense_symbol})
505
506 Converts a sense symbol to a set `set` such that
507 `@constraint(model, func sense_symbol 0)` is equivalent to
508 `@constraint(model, func in set)` for any `func::AbstractJuMPScalar`.
509
510 ## Example
511
512 Once a custom set is defined you can directly create a JuMP constraint with it:
513 ```jldoctest operator_to_set
514 julia> struct CustomSet{T} <: MOI.AbstractScalarSet
515 value::T
516 end
517
518 julia> Base.copy(x::CustomSet) = CustomSet(x.value)
519
520 julia> model = Model();
521
522 julia> @variable(model, x)
523 x
524
525 julia> cref = @constraint(model, x in CustomSet(1.0))
526 x ∈ CustomSet{Float64}(1.0)
527 ```
528
529 However, there might be an appropriate sign that could be used in order to
530 provide a more convenient syntax:
531 ```jldoctest operator_to_set
532 julia> JuMP.operator_to_set(::Function, ::Val{:⊰}) = CustomSet(0.0)
533
534 julia> MOIU.supports_shift_constant(::Type{<:CustomSet}) = true
535
536 julia> MOIU.shift_constant(set::CustomSet, value) = CustomSet(set.value + value)
537
538 julia> cref = @constraint(model, x ⊰ 1)
539 x ∈ CustomSet{Float64}(1.0)
540 ```
541 Note that the whole function is first moved to the right-hand side, then the
542 sign is transformed into a set with zero constant and finally the constant is
543 moved to the set with `MOIU.shift_constant`.

711 parse_constraint_call(
712 error_fn::Function,
713 is_vectorized::Bool,
714 ::Val{op},
715 args...,
716 )
717
718 Implement this method to intercept the parsing of a `:call` expression with
719 operator `op`.
720
721 !!! warning
722 Extending the constraint macro at parse time is an advanced operation and
723 has the potential to interfere with existing JuMP syntax. Please discuss
724 with the [developer chatroom](https://jump.dev/chatroom) before
725 publishing any code that implements these methods.
726
727 ## Arguments
728
729 * `error_fn`: a function that accepts a `String` and throws the string as an
730 error, along with some descriptive information of the macro from which it was
731 thrown.
732 * `is_vectorized`: a boolean to indicate if `op` should be broadcast or not
733 * `op`: the first element of the `.args` field of the `Expr` to intercept
734 * `args...`: the `.args` field of the `Expr`.
735
736 ## Returns
737
738 This function must return:
739
740 * `parse_code::Expr`: an expression containing any setup or rewriting code that
741 needs to be called before `build_constraint`
742 * `build_code::Expr`: an expression that calls `build_constraint(` or
743 `build_constraint.(` depending on `is_vectorized`.
744
745 See also: [`parse_constraint_head`](@ref), [`build_constraint`](@ref)
746 """
747 function parse_constraint_call(
748 error_fn::Function,
749 ::Bool,
750 ::Val{T},
751 args...,
752 ) where {T}
753 return error_fn(
754 "Unsupported constraint expression: we don't know how to parse " *
755 "constraints containing the operator $T.\n\nIf you are writing a " *
756 "JuMP extension, implement " *
757 "`parse_constraint_call(::Function, ::Bool, ::Val{$T}, args...)",
758 )
759 end

761 # `@constraint(model, func in set)`
762 # `@constraint(model, func ∈ set)`
763 function parse_constraint_call(
764 error_fn::Function,
765 vectorized::Bool,
766 ::Union{Val{:in},Val{:∈}},
767 func,
768 set,
769 )
770 f, parse_code = _rewrite_expression(func)
771 build_call = if vectorized
772 :(build_constraint.($error_fn, _desparsify($f), $(esc(set))))
773 else
774 :(build_constraint($error_fn, $f, $(esc(set))))
775 end
776 return parse_code, build_call
777 end

801 """
802 parse_constraint_call(
803 error_fn::Function,
804 vectorized::Bool,
805 ::Val{op},
806 lhs,
807 rhs,
808 ) where {op}
809
810 Fallback handler for binary operators. These might be infix operators like
811 `@constraint(model, lhs op rhs)`, or normal operators like
812 `@constraint(model, op(lhs, rhs))`.
813
814 In both cases, we rewrite as `lhs - rhs in operator_to_set(error_fn, op)`.
815
816 See [`operator_to_set`](@ref) for details.
817 """
818 function parse_constraint_call(
819 error_fn::Function,
820 vectorized::Bool,
821 operator::Val,
822 lhs,
823 rhs,
824 )
825 func = vectorized ? :($lhs .- $rhs) : :($lhs - $rhs)
826 f, parse_code = _rewrite_expression(func)
827 set = operator_to_set(error_fn, operator)
828 # `_functionize` deals with the pathological case where the `lhs` is a
829 # `VariableRef` and the `rhs` is a summation with no terms.
830 f = :(_functionize($f))
831 build_call = if vectorized
832 :(build_constraint.($error_fn, _desparsify($f), Ref($(esc(set)))))
833 else
834 :(build_constraint($error_fn, $f, $(esc(set))))
835 end
836 return parse_code, build_call
837 end
