46 """
47 CleverDict{K, V}
48
49 A smart storage type for managing sequential objects with non-decreasing integer
50 indices. Note that the integers are `Int64`s.
51
52 Provided no keys are deleted, the backing storage is a `Vector{V}`. Once a key
53 has been deleted, the backing storage switches to an `OrderedDict{K, V}`.
54
55 Use the `add_item` to enforce adding item in sequence. Once an object is added
56 out of order `add_item` does not work anymore and the storage is switched to
57 `OrderedDict{K, V}` if it is not one already.
58
59 The i'th ordered element can be obtained with `c[LinearIndex(i)]`.
60
61 Note that querying a `LinearIndex` immediately after deleting a key via
62 `delete!` is very slow. (It requires a rebuild of an ordered list of variables.)
63
64 Store an item `val` using `add_item(c::CleverDict, val)`. `add_item` returns a
65 key corresponding to the stored item.
66
67 Overload the functions `index_to_key` and `key_to_index` to enable mappings
68 between the integer index of the vector and the dictionary key.
69
70 ## Example
71
72 ```julia
73 struct MyKey
74 x::Int64
75 end
76 index_to_key(::Type{MyKey}, i::Int64) = MyKey(i)
77 key_to_index(key::MyKey) = key.x
78 ```
79 """

225 function Base.getindex(c::CleverDict{K,V}, index::LinearIndex)::V where {K,V}
226 if !(1 <= index.i <= length(c))
227 throw(KeyError(index))
228 end
229 # Get the `index` linear element. If `c.vector` is currently `nothing`
230 # (that is, there has been a deletion), rebuild `c.vector`. This is a
231 # trade-off: We could ensure `c.vector` is always updated, but this requires
232 # a `splice!` in `delete!`, making deletions costly. However, it makes this
233 # `getindex` operation trivial because we would never have to rebuild the
234 # vector.
235 # The current implemented approach offers quick deletions, but an expensive
236 # rebuild the first time you query a `LinearIndex` after a deletion or a new
237 # key is added. Once the rebuild is done, there are quick queries until the
238 # next deletion or addition. Thus, the worst-case is a user repeatedly
239 # deleting a key and then querying a LinearIndex (for example, getting the MOI
240 # objective function).
241 if !_is_dense(c) && length(c.dict) != length(c.vector)
242 c.vector = Vector{V}(undef, length(c))
243 for (i, val) in enumerate(values(c.dict))
244 c.vector[i] = val
245 end
246 end
247 return c.vector[index.i]::V
248 end
