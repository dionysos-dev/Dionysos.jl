162 """
163 GenericModel{T}([optimizer_factory]; kwargs...) where {T<:Real}
164
165 Create a new instance of a JuMP model.
166
167 If `optimizer_factory` is provided, the model is initialized with the optimizer
168 using `set_optimizer(model, optimizer_factory; kwargs...)`. See
169 [`set_optimizer`](@ref) for details on `kwargs`.
170
171 If `optimizer_factory` is not provided, use [`set_optimizer`](@ref) to set the
172 optimizer before calling [`optimize!`](@ref).
173
174 ## Value type `T`
175
176 Passing a type other than `Float64` as the value type `T` is an advanced
177 operation. The value type must match that expected by the chosen optimizer.
178 Consult the optimizers documentation for details.
179
180 If not documented, assume that the optimizer supports only `Float64`.
181
182 Choosing an unsupported value type will throw an [`MOI.UnsupportedConstraint`](@ref)
183 or an [`MOI.UnsupportedAttribute`](@ref) error, the timing of which (during the
184 model construction or during a call to [`optimize!`](@ref)) depends on how the
185 solver is interfaced to JuMP.
186
187 ## Example
188
189 ```jldoctest
190 julia> model = GenericModel{BigFloat}();
191
192 julia> typeof(model)
193 GenericModel{BigFloat}
194 ```
195 """
196 function GenericModel{T}(
197 @nospecialize(optimizer_factory = nothing);
198 kwargs...,
199 ) where {T<:Real}
200 inner = MOI.Utilities.UniversalFallback(MOI.Utilities.Model{T}())
201 cache = MOI.Utilities.CachingOptimizer(inner, MOI.Utilities.AUTOMATIC)
202 model = direct_generic_model(T, cache)
203 if optimizer_factory !== nothing
204 set_optimizer(model, optimizer_factory; kwargs...)
205 end
206 return model
207 end

215 Return a new JuMP model using [`backend`](@ref) to store the model and solve it.
216
217 As opposed to the [`Model`](@ref) constructor, no cache of the model is

220
221 ## Notes
222
223 The absence of a cache reduces the memory footprint but, it is important to bear
224 in mind the following implications of creating models using this *direct* mode:
225

227 constraints or adding variables/constraints after solving, an error is

229 situations can be dealt with by storing the modifications in a cache and

231 * No constraint bridging is supported by default.
232 * The optimizer used cannot be changed the model is constructed.
233 * The model created cannot be copied.

467 """
468 unsafe_backend(model::GenericModel)
469
470 Return the innermost optimizer associated with the JuMP model `model`.
471
472 **This function should only be used by advanced users looking to access
473 low-level solver-specific functionality. It has a high-risk of incorrect usage.
474 We strongly suggest you use the alternative suggested below.**
475
476 See also: [`backend`](@ref).
477
478 To obtain the index of a variable or constraint in the unsafe backend, use
479 [`optimizer_index`](@ref).
480
481 ## Unsafe behavior
482
483 This function is unsafe for two main reasons.
484
485 First, the formulation and order of variables and constraints in the unsafe
486 backend may be different to the variables and constraints in `model`. This
487 can happen because of bridges, or because the solver requires the variables or
488 constraints in a specific order. In addition, the variable or constraint index
489 returned by [`index`](@ref) at the JuMP level may be different to the index of
490 the corresponding variable or constraint in the `unsafe_backend`. There is no
491 solution to this. Use the alternative suggested below instead.
492
493 Second, the `unsafe_backend` may be empty, or lack some modifications made to
494 the JuMP model. Thus, before calling `unsafe_backend` you should first call
495 [`MOI.Utilities.attach_optimizer`](@ref) to ensure that the backend is
496 synchronized with the JuMP model.
497
498 ```jldoctest
499 julia> import HiGHS
500
501 julia> model = Model(HiGHS.Optimizer)
502 A JuMP Model
503 ├ solver: HiGHS
504 ├ objective_sense: FEASIBILITY_SENSE
505 ├ num_variables: 0
506 ├ num_constraints: 0
507 └ Names registered in the model: none
508
509 julia> MOI.Utilities.attach_optimizer(model)
510
511 julia> inner = unsafe_backend(model)
512 A HiGHS model with 0 columns and 0 rows.
513 ```
514
515 Moreover, if you modify the JuMP model, the reference you have to the backend
516 (that is, `inner` in the example above) may be out-dated, and you should call
517 [`MOI.Utilities.attach_optimizer`](@ref) again.
518
519 This function is also unsafe in the reverse direction: if you modify the unsafe
520 backend, for example, by adding a new constraint to `inner`, the changes may be
521 silently discarded by JuMP when the JuMP `model` is modified or solved.
522
523 ## Alternative
524
525 Instead of `unsafe_backend`, create a model using [`direct_model`](@ref) and
526 call [`backend`](@ref) instead.
527
528 For example, instead of:
529
530 ```jldoctest
531 julia> import HiGHS
532
533 julia> model = Model(HiGHS.Optimizer);
534
535 julia> set_silent(model)
536
537 julia> @variable(model, x >= 0)
538 x
539
540 julia> MOI.Utilities.attach_optimizer(model)
541
542 julia> highs = unsafe_backend(model)
543 A HiGHS model with 1 columns and 0 rows.
544
545 julia> optimizer_index(x)
546 MOI.VariableIndex(1)
547 ```
548
549 Use:
550
551 ```jldoctest
552 julia> import HiGHS
553
554 julia> model = direct_model(HiGHS.Optimizer());
555
556 julia> set_silent(model)
557
558 julia> @variable(model, x >= 0)
559 x
560
561 julia> highs = backend(model) # No need to call `attach_optimizer`.
562 A HiGHS model with 1 columns and 0 rows.
563
564 julia> index(x)
565 MOI.VariableIndex(1)
566 ```
