6 """
7 @variable(model, expr, args..., kw_args...)
8
9 Add a variable to the model `model` described by the expression `expr`, the
10 positional arguments `args` and the keyword arguments `kw_args`.
11
12 ## Anonymous and named variables
13
14 `expr` must be one of the forms:
15
16 * Omitted, like `@variable(model)`, which creates an anonymous variable
17 * A single symbol like `@variable(model, x)`
18 * A container expression like `@variable(model, x[i=1:3])`
19 * An anonymous container expression like `@variable(model, [i=1:3])`
20
21 ## Bounds
22
23 In addition, the expression can have bounds, such as:
24
25 * `@variable(model, x >= 0)`
26 * `@variable(model, x <= 0)`
27 * `@variable(model, x == 0)`
28 * `@variable(model, 0 <= x <= 1)`
29
30 and bounds can depend on the indices of the container expressions:
31
32 * `@variable(model, -i <= x[i=1:3] <= i)`
33
34 ## Sets
35
36 You can explicitly specify the set to which the variable belongs:
37
38 * `@variable(model, x in MOI.Interval(0.0, 1.0))`
39
40 For more information on this syntax, read
41 [Variables constrained on creation](@ref).
42
43 ## Positional arguments
44
45 The recognized positional arguments in `args` are the following:
46
47 * `Bin`: restricts the variable to the [`MOI.ZeroOne`](@ref) set, that is,
48 `{0, 1}`. For example, `@variable(model, x, Bin)`. Note: you cannot use
49 `@variable(model, Bin)`, use the `binary` keyword instead.
50 * `Int`: restricts the variable to the set of integers, that is, ..., -2, -1,
51 0, 1, 2, ... For example, `@variable(model, x, Int)`. Note: you cannot use
52 `@variable(model, Int)`, use the `integer` keyword instead.
53 * `Symmetric`: Only available when creating a square matrix of variables, that
54 is when `expr` is of the form `varname[1:n,1:n]` or `varname[i=1:n,j=1:n]`,
55 it creates a symmetric matrix of variables.
56 * `PSD`: A restrictive extension to `Symmetric` which constraints a square
57 matrix of variables to `Symmetric` and constrains to be positive
58 semidefinite.
59
60 ## Keyword arguments
61
62 Four keyword arguments are useful in all cases:
63
64 * `base_name`: Sets the name prefix used to generate variable names. It
65 corresponds to the variable name for scalar variable, otherwise, the
66 variable names are set to `base_name[...]` for each index `...` of the axes
67 `axes`.
68 * `start::Float64`: specify the value passed to `set_start_value` for each
69 variable
70 * `container`: specify the container type. See
71 [Forcing the container type](@ref variable_forcing) for more information.
72 * `set_string_name::Bool = true`: control whether to set the
73 [`MOI.VariableName`](@ref) attribute. Passing `set_string_name = false` can
74 improve performance.
75
76 Other keyword arguments are needed to disambiguate sitations with anonymous
77 variables:
78
79 * `lower_bound::Float64`: an alternative to `x >= lb`, sets the value of the
80 variable lower bound.
81 * `upper_bound::Float64`: an alternative to `x <= ub`, sets the value of the
82 variable upper bound.
83 * `binary::Bool`: an alternative to passing `Bin`, sets whether the variable
84 is binary or not.
85 * `integer::Bool`: an alternative to passing `Int`, sets whether the variable
86 is integer or not.
87 * `set::MOI.AbstractSet`: an alternative to using `x in set`
88 * `variable_type`: used by JuMP extensions. See
89 [Extend `@variable`](@ref extend_variable_macro) for more information.
90
91 ## Example
92
93 The following are equivalent ways of creating a variable `x` of name `x` with
94 lower bound 0:
95 ```jldoctest
96 julia> model = Model();
97
98 julia> @variable(model, x >= 0)
99 x
100 ```
101
102 ```jldoctest
103 julia> model = Model();
104
105 julia> @variable(model, x, lower_bound = 0)
106 x
107 ```
108
109 ```jldoctest
110 julia> model = Model();
111
112 julia> x = @variable(model, base_name = "x", lower_bound = 0)
113 x
114 ```
115
116 Other examples:
117
118 ```jldoctest
119 julia> model = Model();
120
121 julia> @variable(model, x[i=1:3] <= i, Int, start = sqrt(i), lower_bound = -i)
122 3-element Vector{VariableRef}:
123 x[1]
124 x[2]
125 x[3]
126
127 julia> @variable(model, y[i=1:3], container = DenseAxisArray, set = MOI.ZeroOne())
128 1-dimensional DenseAxisArray{VariableRef,1,...} with index sets:
129 Dimension 1, Base.OneTo(3)
130 And data, a 3-element Vector{VariableRef}:
131 y[1]
132 y[2]
133 y[3]
134
135 julia> @variable(model, z[i=1:3], set_string_name = false)
136 3-element Vector{VariableRef}:
137 _[7]
138 _[8]
139 _[9]
140 ```

380 # There is not way to determine at parsing time which of lhs or rhs is the
381 # variable name and which is the value if both are symbols. For instance,
382 # lhs could be the Symbol `:x` and rhs could be the Symbol `:a` where a
383 # variable `a` is assigned to 1 in the local scope. Knowing this, we know
384 # that `x` is the variable name but at parse time there is now way to know
385 # that `a` has a value.

391 var,
392 value,
393 )
394 set = parse_one_operator_variable(
395 error_fn,
396 info_expr,
397 Val(sense),
398 _esc_non_constant(value),
399 )
400 return var, set
401 end

611 build_variable(
612 error_fn::Function,
613 info::VariableInfo,
614 args...;
615 kwargs...,
616 )
617
618 Return a new [`AbstractVariable`](@ref) object.
619
620 This method should only be implemented by developers creating JuMP extensions.
621 It should never be called by users of JuMP.
622
623 ## Arguments
624
625 * `error_fn`: a function to call instead of `error`. `error_fn` annotates the
626 error message with additional information for the user.
627 * `info`: an instance of [`VariableInfo`](@ref). This has a variety of fields
628 relating to the variable such as `info.lower_bound` and `info.binary`.
629 * `args`: optional additional positional arguments for extending the
630 [`@variable`](@ref) macro.
631 * `kwargs`: optional keyword arguments for extending the [`@variable`](@ref)
632 macro.
633
634 See also: [`@variable`](@ref)
635
636 !!! warning
637 Extensions should define a method with ONE positional argument to dispatch
638 the call to a different method. Creating an extension that relies on
639 multiple positional arguments leads to `MethodError`s if the user passes the
640 arguments in the wrong order.
641
642 ## Example
643
644 ```julia
645 @variable(model, x, Foo)
646 ```
647 will call
648 ```julia
649 build_variable(error_fn::Function, info::VariableInfo, ::Type{Foo})
650 ```
651
652 Passing special-case positional arguments such as `Bin`, `Int`, and `PSD` is
653 okay, along with keyword arguments:
654 ```julia
655 @variable(model, x, Int, Foo(), mykwarg = true)
656 # or
657 @variable(model, x, Foo(), Int, mykwarg = true)
658 ```
659 will call
660 ```julia
661 build_variable(error_fn::Function, info::VariableInfo, ::Foo; mykwarg)
662 ```
663 and `info.integer` will be true.
664
665 Note that the order of the positional arguments does not matter.
666 """

760 @variable(model, x[1:2] == fx)
761 ```
762 use
763 ```julia
764 @variable(model, x[i=1:2] == fx[i])
765 ```
766 or
767 ```julia
768 @variable(model, x[1:2])
769 fix.(x, fx)
770 ```
771 """,
772 )
773 elseif info.start isa AbstractArray
774 error_fn(
775 """
776 Passing arrays as variable starts without indexing them is not supported.
777
778 Instead of:
779 ```julia
780 @variable(model, x[1:2], start = x0)
781 ```
782 use
783 ```julia
784 @variable(model, x[i=1:2], start = x0[i])
785 ```
786 or
787 ```julia
788 @variable(model, x[1:2])
789 set_start_value.(x, x0)
790 ```
791 """,
792 )
793 end
794 return ScalarVariable(info)
795 end
